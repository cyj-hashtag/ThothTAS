# 新编辑功能使用说明

从 `dist/editor/ThothTAS.Editor.exe` 启动编辑器。在项目根目录也可执行：

```powershell
.\dist\editor\ThothTAS.Editor.exe --root D:\Workspace4All\ThothTAS --script .\examples\basic-1.tas
```

## 行旁帧标记与语言切换

高亮行后会显示蓝色 `--- 34`，表示当前段已执行34帧；它随播放、逐帧和滚动更新，不写入脚本、复制文本或保存文件。改稿后草稿标记清除，运行快照仍保持准确显示。

工具栏“语言 / Language”切换“简体中文 / English”，无需重启回放，选择在本机保留。英文下拼接按钮为“Compose TAS…”。拼接顺序窗口支持添加脚本、移除、上移和下移。脚本格式、关卡名和原始游戏诊断不因界面语言改变。

## 看当前执行位置与过关记录

打开 `examples/basic-1.tas`，校验后播放。“运行快照（只读）”页是本次实际使用的冻结文本，黄色背景标出刚执行的输入源行；右侧“输入段”显示段内第几帧 / 段长度。这里的帧是完整输入周期，每周期为 1/60 秒。

草稿与快照相同时，草稿也可显示相同高亮。播放中修改、打开或保存另一份草稿后，草稿取消执行行标记，运行快照保持原文本与正确高亮。此时保存只改变草稿；点击“重新回放”才使用新文本。章节等待自然转场时没有输入源行，界面显示等待状态。

右侧底部列表分别显示“过关”和“入场”，后者是下一关玩家真正激活的边界。用户当前 `basic-1.tas` 的真实记录是 Basic-1 在第 147 帧过关，Basic-2 在第 273 帧玩家激活。它们不是同一个事件；转场动画和激活等待也占实际回放周期。

## 同进程快速重置练习

“重新回放”旁的“同进程快速重置”默认关闭。关闭时重新回放启动新进程；勾选时先在帧边界暂停，恢复工具的固定存档，冻结最新草稿并重新加载指定起点，保留当前游戏 PID。

同进程重置仍创建新的运行目录和 `script.tas`，不会把两次记录混在一起。种子、脚本可改变，窗口尺寸保持最初值。游戏启动时的 Unity 日志仍在第一次冷启动目录，新目录的 `host-run.json` 用 `initialUnityLogPath` 指向它。

这个选项用于减少反复练习的启动等待。Unity 原生时间、物理内部状态及部分进程内状态不会全部清零，不能把暖重置声明为冷启动等价。检查完整脚本的可重复性时，使用下方独立冷进程 `verify`；“重复验证 ×5”也会启动独立进程。

## 拼接当前两个单关脚本

点击“拼接脚本”，选择 `examples/basic-1.tas` 和 `examples/basic-2.tas`。在顺序确认窗中，把 basic-1 放在上方、basic-2 放在下方，然后点击“生成拼接草稿”。两份源文件仅被读取，内容保持不变。

点击“另存为”，保存到一个新文件，例如 `work/basic-1-basic-2.tas`。拼接文本使用统一 Seed，并生成 `Room,Basic-1` 和 `Room,Basic-2` 章节，注释保留各段来源。输入来源顺序必须符合自然关卡相邻关系，种子不一致、缺少相邻关卡或重复顺序会报错。

Room 章节按实际过关和入场边界执行。关卡提前完成后，当前章节剩余尾部输入被跳过；等待自然转场期间使用零输入；下一关玩家激活后，下一章节从本地第 1 帧开始。某章节用完输入预算仍未过关时会失败，便于回去修改输入。

也可使用命令行，不打开游戏就生成新文本：

```powershell
.\dist\host\ThothTAS.Host.exe compose --root D:\Workspace4All\ThothTAS --out .\work\basic-1-basic-2.tas .\examples\basic-1.tas .\examples\basic-2.tas
```

命令行按输入参数顺序拼接，拒绝覆盖任一输入或已存在的输出。已有同名输出时，请选择新文件名。

## 连段必须实际复核

两个单关脚本各自在指定起点成功，同一种子也不能保证第二关的独立起点等于连续进入的起点。Seed 只确定整次回放的随机流起点；Room 边界不重新播种。第一关和转场已经消耗随机值，连段的随机位置、时间及入场过程可能与直接从 Basic-2 开始不同。

拼接通过只表示文本、种子和关卡相邻关系合法。完整连续回放还需实际冷进程复核，必要时调整第二章节的输入：

```powershell
.\dist\host\ThothTAS.Host.exe verify .\work\basic-1-basic-2.tas --root D:\Workspace4All\ThothTAS --count 2 --modes --out .\work\verification\basic-joined
```

该命令运行两次连续冷回放，再比较暂停继续、逐帧、0.5×、2×，总共六个独立进程。比较覆盖初始基线、全部实际帧和完整随机调用记录；失步时显示首个不同帧和字段。目标速度受记录、渲染、物理及磁盘性能限制，实际播放速度可能低于设置值。

用户当前两份脚本预算为 274 + 525 = 799 帧；这一对已完成上述六次真实流程，实际连续回放均在第 495 帧完成两关，逐帧与完整随机记录一致。已生成 `examples/composed/basic-1-basic-2.tas`，可以直接打开。证据在 `work/acceptance/editing-final/joined/report.json` 与 `report.md`。新增编辑器操作专项也已通过：`work/acceptance/editor-editing-final/editor-editing-report.json`，17 项检查覆盖高亮、段进度、事件列表、同 PID 新运行、拼接与实际断线错误显示。此结果仅覆盖该版本和这些脚本，不表示任意单关组合都可直接连贯运行。

最终模块的焦点专项在 `work/acceptance/editor-runtime-release-2`，已验证六轮真实游戏/编辑器焦点切换、实体方向键、播放中改稿保存及速度/暂停/逐帧的逐帧一致性。总报告见 [公开实际验证摘要](public/verification-20261013.md)。

## 社区计时器与重置提速

已适配 rmadlal v2.8 的计时器和窗口。首次运行 `scripts/Prepare-CommunityMod.ps1`，然后在编辑器勾选“社区计时器”。只在内存中加载社区程序集，窗口仍由编辑器配置；计时器按完整60Hz周期推进，暂停与变速不改变同一TAS结果，不能视为普通墙钟RTA。切换配置在下次重新回放生效并自动启动新进程。

同进程重置复用已加载的声音库，恢复其层级、选择器和音源状态，重建其他玩法场景与对象池。勾选“同进程快速重置”后，重新回放从约2.56秒缩短至实测约0.55秒；首次启动仍需正常加载。`coldEquivalent=false`：暖回放可能存在浮点和长路径随机记录差异，完整精确验证继续使用独立冷进程。自动实测入口为 `dist/host/ThothTAS.Host.exe verify-reset examples/basic-1.tas --count 5`，JSON 同时列出整个回放的字段差异。[本次实际报告](public/reset-subsecond-20261013.md)。
