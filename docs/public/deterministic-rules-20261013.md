# 确定性修改规则与同进程快重播（v0.4.0）

本轮实际游戏验证通过。正式样本共 **169 次同进程重置**，全部低于一秒：**0.479–0.644 秒**，中位数 0.523 秒。统计使用控制端等待玩家激活后的帧0边界；编辑器样本包含正式“重新回放”按钮恢复并放行播放的全过程。首次启动通常约8–10秒，不在一秒目标内。

## 使用

打开更新后的编辑器，勾选 **“确定性规则（修改游戏）”**，首次播放后保持游戏运行，之后点击“重新回放”。也可在 Version 后添加 `Rules,Deterministic-1`。旧文件不自动改规则；新草稿默认修改规则。切换规则、社区Mod或停止游戏后需要新进程。

源码在 `src/ThothTAS.Runtime/DeterministicRules.cs`、`src/ThothTAS.Preloader/Patcher.cs`。该模式固定三个程序集158处已扫描直接Unity随机调用的结果：浮点Range取中点、整数Range取合法中间值、value取0.5，不消耗这些调用的Unity随机序列。Seed不改变这些结果。物理改为60Hz，关闭刚体插值、锁定物理转动、取消死亡慢动作；实际托管Update按稳定层级/类型/组件顺序执行，游戏及相关音频逻辑时钟按帧计算。移动、射击、敌人、碰撞及死亡仍在游戏中执行。

**玩法与原版不同，旧TAS可能需要重新调帧和角度。** 私人Basic-3原稿在新规则下稳定死亡，本轮证明重复一致，没有声称它已经通关。原规则仍保留，正式重新回放使用独立进程。

自然流程64关各进入两次，共128次暖重置，在同一个PID 45948 中切换关卡，零输入基线和下一完整帧精确一致，原生日志无上述异常。该项目另有Teleporters-5资源：探索时记录相同，但发现缺失core渲染引用；它不属于64关自然序列，排除在正式支持范围。真实反例已确认新验证入口会拒绝该异常，不能把“同样损坏”计为确定性通过。

Basic-3单独运行5次独立进程，再加暂停继续、逐帧、0.5×和2×，合计9次、每次337帧，全部玩法/随机/完整阶段精确一致。正式编辑器分别在stock与社区v2.8配置下执行首次启动和3次同PID重新回放，包含变速、暂停、逐帧、运行中改稿保存、规则切换拒绝和不可变快照检查；六次按钮耗时均低于一秒。修改规则下Seed2与Seed1日志完全相同，验证随机结果已经固定。原规则Basic-1两个独立进程274帧比较通过。

本轮共审核 22142 个修改规则实际输入帧、22 个健康原生Unity日志，玩法随机清单观察到 90 个静态调用点；未执行路径不由静态接管数158证明。纯Core测试140项、规则界面14项及实际未保存弹窗/崩溃恢复19项均通过；这些检查不代替游戏回放。

## 证据与自动复核

[可机器读取的摘要](deterministic-verification-20261013.json) 保存模块SHA256、各脚本日志SHA256、PID、耗时和本机原始报告路径。完整原始CIL、游戏、私人输入与控制令牌不上传。

```powershell
.\scripts\Verify-Deterministic.ps1 -ScriptPath .\examples\basic-1.tas -Count 5 -Modes
.\scripts\Verify-Deterministic.ps1 -Count 5 -CommunityMod -CheckAllStarts
```

CheckAllStarts需要.NET 10 SDK。示例输入在 `examples/modified`，不保证每条能通关。最初原型的玩法/随机相同而阶段顺序不同，已通过稳定实际Update调度修正；原型日志保留在本机，未删除差异或过滤阶段来宣称通过。

代表性暖重播报告采用与最终包相同的Runtime/Preloader；最终Host额外加入原生异常拒绝，代表性正例日志亦已完整复审。未提供跨电脑、全部战斗路径一致性或任何Windows调度状态下一秒内的保证；这些是当前机器本轮测量结果。没有即时存档、倒放或寻址跳帧。原生PhysX内部并未全部清零，原生时钟与bootstrap记录仍单独保留；画面像素和实际音频输出未做逐字节比较。独立单关成功仍不能保证自然拼接成功，必须复核完整连续流程。
