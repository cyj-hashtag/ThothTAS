# 同进程重置提速：实际游戏报告

日期：2026-10-13。范围：本机、THOTH-2019-09-10-174628-r239、原版游戏配置。此报告测量真正运行的 THOTH 副本，未以模拟或编译结果代替游戏测试。

同一份 Basic-1／Seed 1／8 帧零输入脚本，旧版四次暖重置为 **6.150、6.358、6.454、6.439 秒**，平均 **6.351 秒**；新版四次为 **2.590、2.566、2.524、2.556 秒**，平均 **2.559 秒**，耗时减少约 **60%**。各组在自己的同一个实际游戏 PID 内重置；旧组与新组使用独立进程，以加载各自模块。

另用用户原始 `examples/basic-1.tas`（274 帧，SHA256 见 JSON）执行冷启动及五次同进程重置：

| 暖重置 | 到帧 0 暂停边界的耗时 | 实际播放帧数 |
|---|---:|---:|
| 1 | 2.711 秒 | 274 |
| 2 | 2.540 秒 | 274 |
| 3 | 2.420 秒 | 274 |
| 4 | 2.586 秒 | 274 |

五次中位耗时 **2.552 秒**。41 项检查通过；真实 PID 保持不变，每次恢复玩家初始位置、存活/未过关状态及零输入，之后都实际播放到 274 帧。源脚本原始字节未变。六次完整随机记录文件的 SHA256 全部相同。

连续五次暖基线均为 GameObject 3321、Mesh 122、Material 319、Texture 171、登记持久根 15，没有本次逐次累积；冷基线 Material 为 320。资源统计是本次有限运行的观察，不是长期内存保证。

提速主要来自移除每次重置重复读取并计算约 176 MB 游戏文件的 SHA256。启动时仍完整校验，随后保持清单及其所有文件的 `FileShare.Read` 句柄，阻止运行期间写入、替换和删除；因此暖重置可以复用仍被锁定的已校验身份。已实际尝试仅请求写入权限打开两个指纹清单及原游戏程序集，均被拒绝；本工具启动的游戏退出后，确认文件锁释放，整个检查没有写入这些文件。

关卡、持久根、对象池及自建 Mesh/Material 仍完整销毁并重新建立，未复用旧的可变实体。新增共享/关卡资源仍会在暖重置前做轻量目录检查；这一保护及空文件探针测试在 41 项运行之后加入，后续集成报告单独记录其验证，不计入上述 41 项。

阶段计时显示，清理与准备通常约 20–40 ms，余下约 2.3 秒主要发生在启动场景重新加载、重建持久库并到菜单就绪；菜单到目标关卡及玩家激活约 0.12 秒。这次修改保留这个完整流程，重置仍需要短暂加载。

**coldEquivalent=false。** 每次冷暖初始基线仍有六个字段差异：Unity 绝对 `Time.time/fixedTime` 与两组音效计时。完整随机文件相同不代表全状态相同，更不能证明物理累积、全关卡或跨电脑一致。正式精确验证继续使用独立进程的 `verify`；同进程重置用于编辑练习。

复现命令：

```powershell
.\dist\host\ThothTAS.Host.exe verify-reset .\examples\basic-1.tas --count 5 --root . --out .\work\reset-check
```

入口生成 `reset-report.json`、`reset-report.md` 和各次独立 run 记录，保留耗时、实际 PID、冷暖基线字段差异、随机文件摘要及资源计数。可公开的逐次证据与模块/脚本摘要见 [JSON 汇总](reset-speed-20261013.json)。社区 Mod 的行为另列于兼容验证报告，不从本报告推断。
